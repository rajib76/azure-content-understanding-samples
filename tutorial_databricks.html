Databricks Document Extraction

Turning PDFs, spreadsheets and CSVs into typed fields with ai_parse_document and ai_extract — from SQL, from REST, and from a local Python script.

The pipeline

Intelligent Document Processing is four functions rather than one service. Each does one job and hands its output to the next, so you can enter the chain at any point — feed ai_extract a parsed document, or just hand it a plain string.

FunctionDoesNotes
ai_parse_documentPDF, DOC/DOCX, PPT/PPTX, images → text, tables, figure descriptions100 pages per document over REST; 120 pages/min per workspace
ai_extractTyped fields from a JSON schemaThe subject of this guide
ai_classifyAssigns one of a predefined label setSupports 500+ labels
ai_prep_searchSemantic chunks for RAGBeta

Credentials

The Agent Bricks docs use $DATABRICKS_HOST and $DATABRICKS_TOKEN without saying where they come from. They are:

  • Host — your workspace URL, straight from the browser address bar. Scheme included, no trailing slash, no path: https://dbc-xxxxxxxx-xxxx.cloud.databricks.com
  • Token — username menu → Settings → Developer → Access tokens → Manage → Generate new token. Copy it immediately; it is shown once.
set once per shell, or put them in .env
export DATABRICKS_HOST="https://dbc-xxxxxxxx-xxxx.cloud.databricks.com"
export DATABRICKS_TOKEN="<token>"
A leading space breaks curl before auth is ever attempted

curl -X POST " https://..." fails with URL rejected: Malformed input to a URL function. And VAR=$(...) curl ... "$VAR" on one line sends an empty bearer header, because the shell expands $VAR before the assignment takes effect — which surfaces as a confusing 401 about an unsupported credential type. Use two statements, or a semicolon.

From SQL

Inside the workspace, ai_extract is an ordinary SQL function. The schema is a JSON string literal here — note that it is a real JSON object over REST, but a string in SQL.

SQL — one document
SELECT ai_extract(
  'Invoice #12345 from Acme Corp for $1,250.00 dated 2024-01-15',
  '{
     "invoice_id":   {"type": "string", "description": "Unique invoice identifier"},
     "vendor_name":  {"type": "string", "description": "Legal business name"},
     "total_amount": {"type": "number", "description": "Total invoice amount"},
     "invoice_date": {"type": "string", "description": "Date in YYYY-MM-DD format"}
   }',
  options => map('version', '2.1'));
SQL — a whole volume, parsed first
SELECT ai_parse_document(content, map('version', '2.0')) AS parsed
FROM READ_FILES('/Volumes/my_catalog/my_schema/my_documents',
                format => 'binaryFile');

That is the scale path: parse a volume into a bronze table, then run ai_extract over the parsed column. Passing the parsed VARIANT rather than a string is what gives citations a page and bounding box instead of a character offset.

From REST

The same function over HTTP, for anything outside the workspace.

POST /api/2.0/ai-functions/ai-extract
curl -X POST "$DATABRICKS_HOST/api/2.0/ai-functions/ai-extract" \
  -H "Authorization: Bearer $DATABRICKS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
  "content": "Invoice #12345 from Acme Corp for $1,250.00 dated 2024-01-15",
  "schema": {
    "vendor_name":  { "type": "string" },
    "total_amount": { "type": "number" }
  },
  "options": { "enable_confidence_scores": true }
}'
The option names differ between SQL and REST

SQL takes camelCase in a map() — enableConfidenceScores, enableCitations. REST takes snake_case in the options object — enable_confidence_scores, enable_citations. Same feature, two spellings.

What comes back

Version 2.1 nests every field under response, and citations are ids pointing into metadata.citations rather than spans carried inline:

response shape, version 2.1
{
  "response": {
    "vendor_name": {
      "value": "Acme Corp",
      "confidence_score": 0.95,       // only with enable_confidence_scores
      "citation_ids": [0]             // only with enable_citations
    }
  },
  "metadata": {
    "version": "2.1",
    "citations": [
      {"id": 0, "start": 0, "stop": 29},          // string input: character span
      {"id": 1, "bbox": [...], "page_id": 0}      // parsed document: page + box
    ]
  },
  "error_message": null
}

Both extras are off by default. Ask for them explicitly or you get bare values.

From a local script

The API takes text, not files — so reading the document is your job. databricks_extract.py does that for three formats and posts the result.

PDF, Excel, CSV
python databricks_extract.py samples/invoice_usd.pdf          schemas/invoice.json
python databricks_extract.py samples/invoice_spreadsheet.xlsx schemas/invoice.json
python databricks_extract.py samples/purchase_orders.csv      schemas/purchase_orders.json

# see the text that would be sent, before spending a call
python databricks_extract.py samples/invoice_usd.pdf --show-text
python databricks_extract.py samples/invoice_usd.pdf --dry-run
python databricks_extract.py samples/invoice_usd.pdf --citations --json out.json
FormatRead withWatch for
.pdfpypdfA scan with no text layer yields nothing — ai_extract has no OCR of its own. Use ai_parse_document for those.
.xlsxopenpyxlFormulas are read as their cached value. A sheet written by a script often has none, and totals read as blank.
.csvstdlib csvRow-capped so a large file does not blow the context limit.

Schemas live in JSON files, not in the script. A tabular source is where this gets interesting — you can ask for values computed across rows, not just copied from one cell:

schemas/purchase_orders.json
{
  "supplier_count":      { "type": "integer", "description": "Number of distinct suppliers." },
  "total_open_value":    { "type": "number",  "description": "Sum of total where status is open or partial." },
  "largest_order_po":    { "type": "string",  "description": "po_number of the row with the highest total." },
  "cancelled_po_numbers":{ "type": "string",  "description": "Comma-separated po_numbers that are cancelled." }
}

Limits worth knowing up front

LimitValue
Fields per schema256
Field name length150 characters
Nesting depth12 levels
Enum values per field500
Total context1,000,000 tokens
ai-extract requests120 per minute per workspace
ai_parse_document pages100 per document over REST

Field types are string, integer, number, boolean and enum, plus nested objects and arrays. Types are validated — an invalid value is an error, not a silent coercion.

Requirements that decide whether this works at all

Serverless compute enabled, Unity Catalog enabled, a serverless budget policy with a nonzero budget, and a region where AI Functions are available. A 404 on the endpoint means one of those is missing — it is a capability answer, not a typo. A 401 is the credential.
